## 第 0 章 · 这个项目一句话是什么

一个以地图为核心、围绕「地点」展开 UGC 内容生产 + 社区互动 + 运营治理的**全栈单体应用**（前后端分离）。前台 C 端（探索地图 / 打卡分享 / 路线 / 社交 / AI 助手）+ 后台运营端（`/admin`，治理与运营）完整闭环。

- 仓库历史包名 `smart-campus`（Maven artifact / 前端服务名 `place-explore-frontend`），产品已泛化为「地点探索与打卡分享平台」，可适配校园 / 城市景点 / 商圈 / 户外路线。
- 后端 ~4960 行 Java / 304 文件；前端 ~29461 行 Vue+JS。
- **技术广度是最大面试价值**：消息队列、可观测性、CI/CD、AOP 审计、空间+向量双检索。

**与"另一个项目"（土地遥感 Multi-Agent）的关系**：两个项目都是本人自研。本项目的部分工程化模块（可观测性 / 通知 Outbox / 登录风控）是从另一个项目迁移复用并适配的——这是**跨项目架构复用能力**的证据（面试加分项）。

## 第 1 章 · 必备背景概念

### 1.1 Spring Boot 4 + Java 21
SB4（2025-11 发布）基于 Spring Framework 7，要求 Java 21。比较新，有踩坑（接口包迁移，见 4.8）。分层：controller / service+impl / repository / entity，经典单体。

### 1.2 前后端分离 + CSR
前端 Vue3 SPA（`createWebHistory`），无 SSR。后端 REST + SSE（AI 对话）。前后端通过 axios + SSE 通信。

### 1.3 JWT 无状态鉴权
STATELESS，CSRF 关闭。token 含 userId/username/role。登出/改密用 revoke_before 黑名单（见 4.3）。

### 1.4 RabbitMQ + Outbox 模式
通知采用 Outbox：业务事务内写 outbox 表 → 定时调度发 MQ → 消费幂等落库。保证"业务成功则通知最终送达"。

### 1.5 可观测性三件套
Actuator 暴露 metrics + Prometheus 采集 + Grafana 可视化。traceId（MDC）串联日志。

### 1.6 RAG + pgvector
POI 向量化（text-embedding-v4，1024 维），pgvector 余弦检索。本项目 RAG 是"空间约束"的（先地理围栏再语义），见 4.1。

## 第 2 章 · 系统全景：一次请求的生命周期

### 2.1 AI 对话生命周期（核心链路）
1. 前端 `AssistantChat.vue` POST `/api/assistant/chat`（SSE）
2. `JwtAuthenticationFilter` 校验 JWT + revoke_before 黑名单 + 用户信息缓存（Redis 5min TTL）
3. `SecurityConfig` 路由鉴权（`/api/assistant/**` 需登录）
4. `AssistantController.chat`：限流（Redis 固定窗口）→ 输入护栏（长度+注入检测）→ 开 SseEmitter（2min 超时）
5. `AssistantChatService.stream`：查多轮记忆 → 语义缓存查询 → 未命中则 `ChatClient.call()`（带工具）→ 写缓存+记忆 → 分块"伪流式"回放
6. 工具调用（`ExplorerTools`）触发空间约束检索（bbox → Haversine → pgvector Top-K）
7. 全程经 `OperationLogAspect`（`@OperationLog`）+ `RequestTraceFilter`（traceId）

### 2.2 通知 Outbox 数据流
业务调 `NotificationServiceImpl.sendNotification` → 业务事务内写 `NotificationEventOutbox`（PENDING）→ `@Scheduled` 调度器扫描 PENDING → 发 RabbitMQ（或无 MQ 同步直发）→ Listener 消费 → `NotificationDeliveryService.deliver` 幂等落库（按 outboxId 去重）→ 失败重试 3 次后 DLX 死信。

## 第 3 章 · 技术选型：为什么是这些

### 3.1 为什么 Spring Boot 4 + Java 21（不是 SB3 / Java 17）
最新栈，体现技术跟进。代价：生态文档少、有包迁移坑（EnvironmentPostProcessor 等，见 4.8）。

### 3.2 为什么 PostGIS + pgvector 双扩展（不自建向量库）
一个 PostgreSQL 同时管空间（PostGIS）+ 向量（pgvector），运维简单。自建镜像 `postgis/postgis` 基础上加装 pgvector（解决 postgis 镜像无 pgvector 的坑）。

### 3.3 为什么 RabbitMQ + Outbox（不直接发 MQ / 不用 Kafka）
Outbox 保证"业务事务与消息发送的一致性"。RabbitMQ 重试+DLX 成熟，适合通知场景；Kafka 过重（通知不需流式高吞吐）。

### 3.4 为什么 AI 助手默认关闭、做成独立模块
`@ConditionalOnProperty(app.assistant.enabled=true)`，关闭时主功能零侵入，可一键回退纯平台。这是"独立模块+配置开关"铁律。

### 3.5 为什么用 Spring AI 而非 LangChain4j
Spring AI 与 Spring 生态原生集成（ChatClient.Builder autoconfigure）。本项目 AI 是增强功能，用 Spring 生态一致。

## 第 4 章 · 核心模块深挖（对照代码逐个击破）

### 4.1 AI 探索助手（最大亮点）

**(a) 空间约束混合检索 RAG**（`AssistantRetrievalService`）—— 与通用 RAG 的核心差异：
三段式「先地理围栏、再语义排序」：
1. **边界框预过滤**：`GeoUtils.calculateBounds`（半径单位千米，调用前 `/1000`）+ `POIRepository.findWithinBounds`（经纬度 BETWEEN）。**刻意不用 ST_DWithin**，复用既有边界框查询。
2. **Haversine 精确过滤**：边界框是外接正方形，剔除四角圆外的点。
3. **候选集内语义 Top-K**：`PoiEmbeddingRepository.findSimilar` 用 pgvector 余弦 `<=>` 在圆内 id 集合近邻。
- 向量表 `poi_embedding` 不交 JPA（Hibernate 不识别 vector 列），用 JdbcTemplate + `?::vector`。HNSW 余弦索引，1024 维对齐 `text-embedding-v4`。
- **动机**：地图域独有——先保证"地理可达"，再谈"语义相关"。

**(b) 语义缓存**（`AssistantSemanticCache`）：pgvector 存历史问答，地理分桶（`%.3f,%.3f` ≈110m）内余弦近邻，阈值 0.95。时效性问题（几点/天气/新闻）正则绕过；多轮请求跳过；fail-open。

**(c) Agent + Tool Use**（`ExplorerTools`）：`@Tool` 暴露 `recommendNearbyPlaces`/`searchPlaces`/`planRoute`/`listCategories`/`getUserPreferences`。全部复用现有 Service/Repository。工具异常返回自然语言错误串（不抛）。

**(d) ToolContext 防 LLM 越权**（核心亮点）：userId 经 `toolContext` 注入，**不进模型可见文本**。ToolContext 不出现在暴露给模型的 JSON Schema 里，模型无法读取/伪造，杜绝"我是 userId=1"越权。

**(e) 伪流式妥协**（`AssistantChatService:131`）：Spring AI 2.0「stream + 工具」对 DashScope 有 `NoSuchElementException` 兼容缺陷（上游 `spring-ai#4790` / `spring-ai-alibaba#1025`，2026-07 验证仍未修复）。官方 workaround = 非流式 `call()`。故用 `call()` + 分块（30 字）回放，放 `boundedElastic` 防阻塞。**这是有据可依的工程妥协**，等上游修复可切真流式。

**(f) 限流 + 护栏 + 多轮记忆**：`AssistantRateLimiter`（Redis 每用户每分钟固定窗口，fail-open）；`AssistantGuard`（长度 500 + 注入正则，定位为"基础防线非绝对安全"）；`AssistantConversationMemory`（Redis List 最近 6 轮，TTL 30min）。

**(g) LLM-as-judge 评测**（`AssistantEvaluationService`）：固定 12 条用例 + LLM 打分 relevance/groundedness。groundedness 校验"推荐地点是否都来自检索候选"防编造。

### 4.2 通知 Outbox 异步可靠投递（架构深度富矿）
- **Outbox 模式**：业务事务内写 outbox（`@Transactional` REQUIRED），业务回滚则事件回滚。
- **三态状态机** PENDING/SUCCESS/FAILED，批量扫描逐条独立提交。**`@Scheduled` 自调用不走代理**，故批量方法故意不加 `@Transactional`（加了反而误导）。
- **失败自动重试**：超 `maxAttempts`（5）转死信。
- **无 MQ 降级**：`rabbitTemplate=null` 时同步直发（不静默丢弃）。
- **消费端幂等**：按 outboxId 去重防 at-least-once 重复。
- **DLX**：主队列绑死信交换机，消费失败超 3 次路由 DLQ。

### 4.3 鉴权与登录风控
- **JWT revoke_before 黑名单 + 1 秒宽限**（`JwtAuthenticationFilter:50`）：登出/改密写 `jwt:revoke_before:{userId}=时间戳`，token 签发时间早于该值则吊销。1 秒宽限：JWT iat 精度只到秒，revoke_before 是毫秒，用 `<=` 会误杀"登出后同秒重登"的新 token。
- **用户信息缓存**：`user:info:{id}` 存 status:role，5min TTL。角色变更主动清缓存（避免 5min 越权窗口）。
- **登录风控**：Redis 优先 + ConcurrentHashMap 本地降级双保险（5 次失败锁 15min）。`ObjectProvider.getIfAvailable` 实现 Redis 未配置降级。定时清理本地降级缓存防随机用户名攻击内存增长。

### 4.4 可观测性（`ObservabilityConfig`）
- Actuator 暴露 health/prometheus/metrics，Prometheus 采集 + Grafana。
- **traceId**：`RequestTraceFilter` 写 MDC，日志 pattern `[%X{traceId:-}]`。
- **SB4 包路径迁移**：`MeterRegistryCustomizer` 从 `actuate.autoconfigure.metrics` 迁到 `micrometer.metrics.autoconfigure`。
- **★actuator 独立 management 端口**（优化1）：`management.server.port=9091`，actuator 端点隔离，主端口 8080 不再暴露 `/actuator`，遵循最小暴露面。`SecurityConfig` `/actuator/**` permitAll（端口隔离保证安全）。

### 4.5 AOP 操作审计（`OperationLogAspect`）
- `@Around("@annotation(operationLog)")`，零命名耦合（Controller 平铺无子包，不能按包名匹配）。
- SpEL 从入参提取 targetId/summary。
- 审计落库 `REQUIRES_NEW` 独立提交，失败不阻断主业务。
- 复用 traceId 串联。

### 4.6 ★对象存储抽象（优化3 · StorageService）
- **接口抽象**：`StorageService`（store/delete）+ `StorageCategory` 枚举（5 分类）+ `LocalFileStorage` 实现。
- **收口**：5 个 service（UserProfile/AdminAnnouncement/AdminActivity/AdminRecommendedRoute/POIShare）原本各自维护 storagePath/saveXxx/deleteXxx + 缩略图，逻辑重复。收口后只调 store/delete。
- **缩略图下沉**：按 `StorageCategory` 配置尺寸（POI 分享 640×640、公告/活动/路线 480×320、头像不生成），store 时自动生成、delete 时清原图+缩略图。
- **路径穿越防护**：resolve 后 startsWith 校验。
- **可扩展**：未来 `OssFileStorage` 实现同一接口，业务无感切换（策略模式）。
- `AdminFileResource` 不收口（目录扫描是治理非存储）。

### 4.7 ★敏感词过滤（优化2 · DFA）
- `SensitiveWordFilter`：DFA 多模式匹配，词库 `sensitive-words.txt`。O(文本长) vs 朴素 O(词数×文本长)。
- 命中策略：**脱敏（`***`）**，不阻断用户发布（比拒绝更平衡）。
- 接入 5 个 UGC 入口（POIShare 分享+回复 / POIReview 评价 / POIApplication 申报 / UserRoute 路线）。
- fail-open（词库加载失败不阻断）。补齐 UGC「事前审核 + 事后举报」闭环。

### 4.8 ★actuator 收窄 + autoconfigure exclusion（优化1）
- actuator 独立端口（见 4.4）。
- **API key 占位串治理**：`AssistantAutoConfigureExclusionEnvironmentPostProcessor`——assistant 关闭时动态注入 `spring.autoconfigure.exclude` 排除 Spring AI `OpenAi*AutoConfiguration`，api-key 可空，去掉 `disabled-when-assistant-off` 占位串。
- **踩坑**：SB4 把 `EnvironmentPostProcessor` 从 `org.springframework.boot.env` 迁到 `org.springframework.boot` 包，spring.factories 注册 key 也要用新 FQN（旧路径仅 deprecated 桥接）。靠测试兜住（`SpringFactoriesLoader.loadFactoryNames` 验证注册）。

### 4.9 ★Flyway 迁移治理（优化4）
- **双轨制**：Hibernate 建初始表（ddl-auto=update 仅全新库首次）+ Flyway 管增量（V{n}）。
- V1 是空 baseline（`SELECT 1`）：既有库 baseline-on-migrate 认领现状，不重放历史。
- **为什么不强求全量 `V2__init.sql`**：30+ 实体 DDL 一致性风险 + `IF NOT EXISTS` 掩盖差异 + 双份真相源。现状是"既有库引入迁移"的工程妥协。
- 历史脚本归档 `db/legacy/`（审计留档，勿执行）。

### 4.10 CI/CD 与部署
- GitHub Actions（push main）：构建 jar+dist → SCP → SSH 执行 deploy/ 脚本。
- 后端 systemd（`place-explore-backend.service`），版本化发布目录 + app.jar 软链接。
- 前端 nginx 托管，版本化 release + current 软链接。`deploy/rollback.sh` 一键回滚。
- Docker Compose 编排 7 服务（PG/Redis/RabbitMQ/Prometheus/Grafana/Backend/Frontend）。

## 第 5 章 · 关键设计权衡总表（面试最爱"为什么不"）

| 决策 | 选了什么 | 放弃了什么 | 为什么 |
|---|---|---|---|
| 架构 | 全栈单体 | 微服务 | 项目阶段收益/风险比最高，无需分布式复杂度 |
| AI 流式 | 伪流式（call+分块） | 真流式 stream | DashScope stream+tools 兼容缺陷（上游未修复），官方 workaround |
| RAG | 空间约束（bbox+Haversine+pgvector） | 纯语义检索 | 地图域必须先保证地理可达 |
| 向量表 | JdbcTemplate（不交 JPA） | JPA 管理 | Hibernate 不识别 vector 类型 |
| AI 工具身份 | ToolContext 注入 userId | 写进 prompt | 防模型伪造身份越权 |
| 通知投递 | Outbox + MQ | 直接发 MQ | 保证业务事务与消息一致 |
| @Scheduled 批量 | 不加 @Transactional | 加事务 | 自调用不走代理，加了误导 |
| 存储抽象 | 缩略图下沉到 LocalFileStorage | 各 service 自管 | 收口重复逻辑，可切换 OSS |
| 敏感词命中 | 脱敏 | 拒绝 | 不阻断用户发布，平衡体验 |
| Flyway | 双轨制（不全量 init） | 纯 Flyway | 30+ 实体 DDL 一致性风险 |
| assistant | 默认关闭独立模块 | 默认开启 | 主功能零侵入，可回退 |
| actuator | 独立 management 端口 | 主端口暴露 | 最小暴露面原则 |

## 第 7 章 · 高频面试问答（背熟）

**Q: 用一分钟介绍这个项目。**
A: 一个地图+社区+运营后台的全栈单体。前台用户在地图上发现地点、打卡分享、规划路线、社交互动、问 AI 助手；后台运营治理。技术栈 Spring Boot 4 + Java 21，PostgreSQL+PostGIS+pgvector，Redis，RabbitMQ，Spring AI。亮点是空间约束 RAG、通知 Outbox 可靠投递、可观测性、CI/CD。

**Q: 你的 RAG 和别人的有什么不同？**
A: 空间约束。先 bbox 预过滤 + Haversine 精确过滤保证地理可达，再在候选集内 pgvector 语义 Top-K。因为地图场景推荐一个语义相关但地理不可达的地点没意义。

**Q: 通知怎么保证不丢？**
A: Outbox 模式。业务事务内写 outbox 表（业务回滚则事件回滚），定时调度发 MQ，消费端按 outboxId 幂等，失败重试 3 次后死信。无 MQ 时同步直发降级。

**Q: AI 助手怎么防越权？**
A: userId 经 ToolContext 注入工具，不进 prompt。ToolContext 不在暴露给模型的 JSON Schema 里，模型无法读取或伪造。所以用户在消息里说"我是 userId=1"也无法读他人数据。

**Q: 为什么用伪流式？**
A: Spring AI 2.0 的 stream+工具调用对 DashScope 有已知兼容缺陷（NoSuchElementException，上游 issue #4790/#1025 未修复）。我用官方 workaround——非流式 call + 分块回放，保住前端 SSE 体验。等上游修复可切真流式。

**Q: 这项目主要 AI 写的吧，你真懂吗？**（核心压力题）
A: ① 两个项目都是我自研，本项目集成了我另一个项目的工程化模块（可观测性/Outbox/风控），是跨项目架构复用能力；② 我能讲清每个关键决策的 why（为什么空间约束 RAG、为什么 Outbox、为什么伪流式）；③ 我做的优化都有据可查（SB4 包迁移排查、DashScope 兼容性追踪、DFA 选型）。

## 第 8 章 · 名词速查

- **Outbox 模式**：业务事务内写事件表，保证业务与消息一致。
- **DFA**：确定有限自动机，多模式字符串匹配，O(n)。
- **Haversine**：球面两点大圆距离公式。
- **bbox**：bounding box，边界框（外接正方形）。
- **ToolContext**：Spring AI 工具调用上下文，只在 Java 侧对工具可见，模型看不到。
- **DLX**：Dead Letter Exchange，死信交换机。
- **baseline-on-migrate**：Flyway 既有库首次迁移时认领现状（不重放历史）。
- **traceId**：链路追踪 ID，写 MDC 串联日志。
- **HITL**：Human-In-The-Loop，人在回路（本项目 AI 模块无 HITL）。
- **revoke_before**：JWT 黑名单方案，记录"该时间前签发的 token 全部吊销"。
